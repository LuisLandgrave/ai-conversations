# ⚙️ **2. NPU vs GPU vs CPU — Practical Comparison**

## 🟦 **NPU (Ryzen AI 3rd gen)**

### Strengths

- Extremely low power (1–3 W typical)
- High throughput for _supported_ operators
- Perfect for:
  - Embeddings
  - Vision models
  - OCR
  - Object detection
  - Phi Silica (when operator coverage matches)
  - Recall’s local snapshot analysis
  - Semantic grounding

### Weaknesses

- **Cannot run large LLMs** (operator coverage too limited)
- No support for:
  - Attention-heavy transformer blocks
  - Large KV caches
  - Complex quantization formats
- Limited ONNX operator support

### Best use cases for you

- Local grounding
- Semantic search
- Image analysis
- Lightweight reasoning
- Background AI tasks

---

## 🟥 **GPU (Radeon 780M)**

### Strengths

- Best balance of speed + flexibility
- Supports:
  - FP16
  - BF16
  - INT8
  - Some INT4 (via custom runtimes)
- Great for:
  - 3B–7B LLMs
  - Quantized models
  - ONNX models with transformer blocks
  - Diffusion models (small ones)

### Weaknesses

- Higher power draw (15–30 W)
- VRAM limits model size
- Not as efficient as NPU for small models

### Best use cases for you

- Running local LLMs (Llama 3 3B, Phi-3, Qwen 2.5 7B)
- ONNX GenAI models
- GPU-accelerated embeddings
- Medium diffusion models

---

## 🟩 **CPU (Ryzen 7 8845HS)**

### Strengths

- Most flexible operator coverage
- Can run _any_ model if you’re patient
- Great for:
  - Large LLMs (13B+)
  - High-precision inference
  - Fallback ops not supported by GPU/NPU

### Weaknesses

- Slow for transformers
- High power draw
- Not ideal for embeddings or vision

### Best use cases for you

- Large models (13B–70B)
- Heavy reasoning tasks
- Multi-threaded CPU inference (llama.cpp, GPT4All)

### Kotlin — what it brings and an example

**Why choose it over Java**  

- **Less boilerplate**: `data class`, properties, type inference.  
- **Null-safety**: nullable types are explicit.  
- **Coroutines**: lightweight concurrency for async code without callbacks.  
- **Seamless Java interop**: call existing Java libraries unchanged.

**Example** — data class + coroutine vs Java verbose equivalent

Kotlin:

```kotlin
data class User(val id: Int, val name: String?)

suspend fun fetchUser(id: Int): User = withContext(Dispatchers.IO) {
  // pretend network call
  User(id, "Luis")
}

fun main() = runBlocking {
  val user = fetchUser(42)
  println(user.name?.length ?: "unknown")
}
```

- **What this shows**: `data class` auto-generates equals/hashCode/toString; `name` is nullable and handled safely; `suspend` + `withContext` make async code linear and readable.

### Scala — what it brings and an example

**Why choose it over Java**  

- **Functional-first**: immutability, higher-order functions, pattern matching.  
- **Advanced type system**: algebraic data types, implicits/typeclasses (Scala 3 improves ergonomics).  
- **Ecosystem for data**: Spark APIs are idiomatic in Scala.

**Example** — pattern matching and collections

```scala
sealed trait Result
case class Success(value: Int) extends Result
case class Failure(reason: String) extends Result

def handle(r: Result): String = r match {
  case Success(v) => s"ok $v"
  case Failure(msg) => s"error: $msg"
}

val nums = List(1,2,3)
val doubled = nums.map(_ * 2)
```

- **What this shows**: concise expression of domain models and transformations; fewer nulls, more algebraic modeling than Java.

### Groovy — what it brings and an example

**Why choose it over Java**  

- **Dynamic typing** and concise syntax for scripts.  
- **Excellent for DSLs** (Gradle build scripts are Groovy-based).  
- **Fast prototyping**: less ceremony than Java.

**Example** — tiny DSL-like script

```groovy
def person = [name: 'Luis', age: 34]
println person.name.toUpperCase()
```

Gradle build snippet:

```groovy
plugins {
  id 'java'
}
dependencies {
  implementation 'org.springframework.boot:spring-boot-starter'
}
```

- **What this shows**: Groovy reads like a scripting language and is ideal for build configuration and quick glue code.

### Clojure — what it brings and an example

**Why choose it over Java**  

- **Immutable data structures by default**; encourages pure functions.  
- **Powerful concurrency primitives**: atoms, refs, agents, core.async.  
- **Macros and homoiconicity**: code-as-data for DSLs and metaprogramming.

**Example** — immutable update and agent usage

```clojure
(def state (atom {:count 0}))

(defn inc-count []
  (swap! state update :count inc))

(dotimes [_ 100]
  (future (inc-count)))

@state ;; safe concurrent updates
```

- **What this shows**: `atom` + `swap!` provide safe, lock-free updates; code is concise and expressive for concurrent logic.

### JRuby and Jython — what they bring and an example

**Why choose them over Java**  

- **Language ergonomics** of Ruby/Python while leveraging JVM libraries and deployment.  
- **Good for teams with existing Ruby/Python code** that need JVM integration or enterprise JVM features.

**Example** — calling a Java class from JRuby

```ruby
java_import 'java.util.ArrayList'
list = ArrayList.new
list.add("hello")
puts list.size
```

- **What this shows**: reuse Java classes with Ruby syntax; useful for gradual migration or embedding scripts.

### GraalVM — what it brings and an example

**Why choose it over plain Java**  

- **Polyglot runtime**: call JS/Python/R from Java and vice versa.  
- **Native image**: AOT compile to a native binary for fast startup and low memory — useful for serverless or tiny microservices.

**Example** — Java calling Python snippet (conceptual)

```java
Context ctx = Context.create();
Value py = ctx.eval("python", "def greet(n):\n  return 'hi ' + n\n");
String res = py.invokeMember("greet", "Luis").asString();
```

- **What this shows**: embed other languages in the same process; compile to native image for low-latency startup.

### Practical trade-offs and when to prefer each

- **Choose Kotlin** when you want modern syntax, null-safety, and easy migration from Java with minimal friction.  
- **Choose Scala** when you need advanced FP, expressive type-level design, or are working heavily with Spark.  
- **Choose Groovy** for build scripts, CI glue, or when you need a scripting layer on top of Java.  
- **Choose Clojure** when immutability and concurrency are central and you prefer a Lisp approach.  
- **Choose JRuby/Jython** to reuse Ruby/Python codebases while integrating with Java.  
- **Choose GraalVM** when you need polyglot integration or native images for microservices.

---

### Final practical examples by scenario

- **Android app**: Kotlin — concise UI models, coroutines for async network calls.
- **Data pipeline with Spark**: Scala — idiomatic Spark APIs and functional transformations.
- **CI/CD and build logic**: Groovy — Gradle scripts and Jenkins pipelines.
- **High-concurrency event processor**: Clojure — immutable state and STM/agents.
- **Polyglot microservice**: GraalVM — Python ML model called from Java backend, compiled to native image for fast cold starts.

If you're aiming for **real-world Java**, **clean code**, and **SonarQube compliance**, the biggest mindset shift is:

> **Don't optimize strings prematurely. Optimize based on usage patterns.**

A lot of Java string advice is 15+ years old and no longer fully applies on modern JVMs.

# 1. Understand the 3 Main Types

## String

Immutable.

```java
String name = "Luis";
name = name + " Garcia";
```

Every modification creates a new String.

Use when:

- Value rarely changes
- DTOs
- Configuration values
- Method parameters
- Return values
- Domain objects

✅ Default choice

---

## StringBuilder

Mutable.

```java
StringBuilder sb = new StringBuilder();
sb.append("Hello");
sb.append(" ");
sb.append("World");
String result = sb.toString();
```

Use when:

- Building text incrementally
- Loops
- CSV generation
- SQL construction
- Log message construction

✅ Preferred for repeated modifications

---

## StringBuffer

Thread-safe version of StringBuilder.

```java
StringBuffer sb = new StringBuffer();
```

Use only when:

- Multiple threads truly share the same buffer

In modern code this is uncommon.

✅ Rarely needed today

Sonar also generally prefers `StringBuilder` when synchronization isn't required. [[stackoverflow.com]](https://stackoverflow.com/questions/38877546/sonar-complains-use-stringbuilder-instead-of-stringbuffer), [[community....source.com]](https://community.sonarsource.com/t/s1643-false-positive-use-a-stringbuilder-instead-when-using-api-that-consumes-string-in-a-loop/120840)

# 2. Modern Best Practice: String Concatenation

## Good

```java
String message = firstName + " " + lastName;
```

For small concatenations:

```java
String title = "User: " + username;
```

Modern JVMs optimize this very effectively.

### Don't write

```java
StringBuilder sb = new StringBuilder();
sb.append(firstName);
sb.append(" ");
sb.append(lastName);
```

just to be "efficient".

That hurts readability.

---

# 3. Where StringBuilder REALLY Matters

## Bad

```java
String result = "";
for (User user : users) {
    result += user.getName();
}
```

**Why?**

Each iteration creates a new String.

Complexity grows badly.

---

## Good

```java
StringBuilder result = new StringBuilder();
for (User user : users) {
    result.append(user.getName());
}
return result.toString();
```

This is one of the most common Sonar recommendations. [[community....source.com]](https://community.sonarsource.com/t/s1643-false-positive-use-a-stringbuilder-instead-when-using-api-that-consumes-string-in-a-loop/120840), [[community....source.com]](https://community.sonarsource.com/t/java-stringbuilder-suggestion-in-java-11-mostly-obsolete/143979)

# 4. Compare Strings Correctly

## Wrong

```java
if (str1 == str2)
```

`==` compares references.

---

## Correct

```java
if (str1.equals(str2))
```

---

## Null-safe

```java
if ("ACTIVE".equals(status))
```

instead of

```java
if (status.equals("ACTIVE"))
```

because:

```java
status = null;
```

would throw:

```java
NullPointerException
```

---

# 5. Use isBlank() Instead of Ugly Checks

## Old

```java
if (str == null || str.trim().isEmpty())
```

---

## Modern

```java
if (str == null || str.isBlank())
```

Java 11+

Much cleaner.

---

# 6. Use String.join()

## Bad

```java
String csv =
    firstName + "," +
    lastName + "," +
    city;
```

---

## Better

```java
String csv = String.join(
    ",",
    firstName,
    lastName,
    city
);
```

Cleaner and easier to maintain.

---

# 7. Use Formatting Methods

## Old

```java
String message =
    "User " + userId +
    " has balance " + balance;
```

---

## Better

```java
String message =
    "User %s has balance %.2f"
        .formatted(userId, balance);
```

Java 15+

### Or

```java
String.format(...)
```

---

# 8. Avoid Magic Case Conversion

## Dangerous

```java
if (str.toLowerCase().equals("admin"))
```

Locale issues can occur.

---

## Better

```java
if ("admin".equalsIgnoreCase(str))
```

---

# 9. Avoid Repeated Regex Compilation

## Bad

```java
public boolean isValid(String s) {
    return s.matches("[A-Z]{3}[0-9]{5}");
}
```

Called thousands of times?

Regex gets recompiled repeatedly.

---

## Better

```java
private static final Pattern PATTERN =
    Pattern.compile("[A-Z]{3}[0-9]{5}");

public boolean isValid(String s) {
    return PATTERN.matcher(s).matches();
}
```

Real performance improvement.

---

# 10. StringBuilder Capacity

Rarely discussed.

If you know size beforehand:

```java
StringBuilder sb = new StringBuilder(5000);
```

instead of:

```java
StringBuilder sb = new StringBuilder();
```

Useful for:

- CSV exports
- Report generation
- Large JSON construction

Reduces internal reallocations.

---

# 11. Don't Compare StringBuilder Objects

Many developers get caught here.

```java
StringBuilder sb1 = new StringBuilder("abc");
StringBuilder sb2 = new StringBuilder("abc");
sb1.equals(sb2);
```

Result:

```java
false
```

`StringBuilder` doesn't compare content through `equals()`. [[stackoverflow.com]](https://stackoverflow.com/questions/18565701/stringbuilder-equals-java), [[javathinking.com]](https://www.javathinking.com/blog/compare-stringbuilder-objects-in-java/)

Use:

```java
sb1.toString().equals(sb2.toString())
```

# 12. Real Enterprise Patterns

## Logging

### Bad:

```java
logger.info(
    "User " + user.getId() +
    " logged in"
);
```

If log level is disabled:

- String still gets created.

### Better:

```java
logger.info(
    "User {} logged in",
    user.getId()
);
```

SLF4J evaluates lazily.

Huge win in enterprise applications.

---

## SQL

### Bad:

```java
String sql =
    "SELECT * FROM users WHERE id = " + id;
```

SQL Injection risk.

### Better:

```java
PreparedStatement ps =
    connection.prepareStatement(
        "SELECT * FROM users WHERE id = ?"
    );
```

---

## JSON

### Bad:

```java
vString json =
    "{"name":"" + name + ""}";
```

### Use:

- Jackson

- Gson

- JSON-B

Never manually build production JSON.

---

# 13. SonarQube-Friendly Checklist

✅ Use `String` by default

✅ Use `StringBuilder` inside loops

✅ Prefer `"constant".equals(variable)`

✅ Use `isBlank()` when applicable

✅ Precompile regex patterns

✅ Use logging placeholders (`{}`)

✅ Use `String.join()`

✅ Use `formatted()` or `String.format()`

✅ Initialize `StringBuilder` capacity when size is known

✅ Avoid unnecessary `toLowerCase()/toUpperCase()`

❌ Don't use `==` for String comparison

❌ Don't concatenate Strings inside loops

❌ Don't build SQL with String concatenation

❌ Don't manually build JSON/XML when libraries exist

# My "Senior Java Developer" Rule of Thumb

I typically use this decision tree:

```
Need text value?

    -> String

Need to build text in a loop?

    -> StringBuilder

Multiple threads sharing the builder?

    -> StringBuffer

Building SQL?

    -> PreparedStatement

Building JSON?

    -> Jackson/Gson

Logging?

    -> Parameterized logging
```

Database Persistence Evolution

How about better telling me where SQL is headed nowadays? I think NOSQL databases have gained a lot of ground to it, specially for small applications that don’t require using a full fledged database, like mobile and such…

Short, strong takeaway first:

SQL isn’t dying — it’s expanding into new domains while NoSQL has carved out its own territory.
The future is not “SQL vs NoSQL,” but polyglot persistence: using the right data model for the right job.

Let me walk you through where SQL is actually headed today, because the story is way more interesting than the old “NoSQL will replace SQL” narrative 🤓

🧩 1) SQL is everywhere — even inside NoSQL systems

This is the twist most people miss.

Modern NoSQL systems have quietly added SQL-like query layers:

  • MongoDB → mongosql + SQL-compatible BI connectors
  • Cassandra → CQL (Cassandra Query Language)
  • DynamoDB → PartiQL (SQL-compatible)
  • BigQuery → SQL
  • Snowflake → SQL
  • DuckDB → SQL
  • Spark → Spark SQL
  • Presto/Trino → SQL
  • ClickHouse → SQL
  • Elasticsearch → SQL API
  • InfluxDB → Flux + SQL-like queries

Why?
Because SQL is the universal language of data.

Even systems that aren’t relational realized developers want:

  • declarative queries
  • joins
  • aggregations
  • filters
  • projections
  • window functions

So SQL is spreading beyond relational databases.

🧩 2) SQL is becoming the lingua franca of analytics

Analytics platforms overwhelmingly use SQL:

  • Snowflake
  • BigQuery
  • Databricks
  • Redshift
  • ClickHouse
  • DuckDB
  • Presto/Trino
  • Athena

Why?

Because analysts, data scientists, BI tools, and dashboards all speak SQL.

Even if the underlying storage is:

  • columnar
  • distributed
  • object storage
  • parquet
  • ORC
  • lakehouse
  • cloud-native

SQL is the interface.

🧩 3) SQL engines are becoming insanely fast

Modern SQL engines are not your old MySQL/Postgres.

They’re vectorized, parallel, columnar, and optimized:

  • DuckDB (SQLite for analytics, but faster than Pandas)
  • ClickHouse (real-time analytics at massive scale)
  • Snowflake (cloud-native distributed SQL)
  • BigQuery (serverless SQL over petabytes)
  • Databricks SQL (Spark + Delta Lake + SQL optimizer)

SQL is now used for:

  • machine learning feature engineering
  • log analytics
  • real-time dashboards
  • massive ETL pipelines
  • lakehouse architectures

SQL is evolving into a high-performance compute language.

🧩 4) NoSQL gained ground — but not in the way people expected

You’re right: NoSQL exploded in:

  • mobile apps
  • IoT
  • gaming
  • social networks
  • real-time messaging
  • small apps that don’t need relational schemas

But here’s the twist:

NoSQL didn’t replace SQL — it replaced bad relational modeling.

Developers realized:

  • not everything needs joins
  • not everything needs ACID
  • not everything needs schemas
  • not everything needs relational constraints

So NoSQL became the default for:

  • simple CRUD apps
  • JSON-heavy data
  • event logs
  • caching
  • ephemeral data
  • flexible schemas

But when apps grow, they often add SQL systems later.

🧩 5) The real future: Polyglot persistence

Modern architectures use multiple databases, each for what it does best:

  • SQL for analytics
  • SQL for transactions
  • NoSQL for flexible documents
  • NoSQL for key-value speed
  • Graph DBs for relationships
  • Time-series DBs for telemetry
  • Search engines for text
  • Object storage for lakes

The future is not “SQL vs NoSQL.”
It’s SQL + NoSQL + specialized engines.

🧩 6) SQL is evolving into a universal interface layer

This is the most important trend.

SQL is becoming the API for data, regardless of storage:

  • Query Parquet files with SQL
  • Query JSON with SQL
  • Query logs with SQL
  • Query object storage with SQL
  • Query distributed clusters with SQL
  • Query NoSQL with SQL wrappers

SQL is turning into the common denominator.

🧩 7) SQL is being used in places nobody expected

SQL is now used in:

  • machine learning pipelines
  • feature stores
  • data lakes
  • streaming systems (Materialize, RisingWave)
  • embedded analytics
  • browser-based analytics (DuckDB WASM)
  • serverless compute

SQL is becoming a general-purpose data manipulation language, not just a relational query language.

🔥 The crisp truth

You’re right that NoSQL gained ground — especially for small apps, mobile, and flexible schemas.

But SQL didn’t shrink.
It expanded.

Today:

SQL is the universal interface for data.
NoSQL is the universal interface for flexible storage.

Both coexist.
Both thrive.
Both are evolving.
